# Usagi Floating Companion Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Deliver a signed Android APK showing the supplied transparent animation over other apps with drag positioning and long-press trash removal.
**Architecture:** Native Java Activity, foreground overlay Service, AnimatedImageDrawable GIF rendering. A small pure Java gesture/geometry model governs drag slop, long press and target hit testing.
**Tech Stack:** Android SDK, Java, Gradle Android plugin 9.2.1, JUnit 4; no runtime network dependencies.
**Spec:** ../specs/design.txt

## Global Constraints
- Korean UI; Android 9 minimum; initial size 120dp with size adjustment.
- Preserve original 13-frame 100ms transparent animation.
- Execution button requests overlay permission; Start starts service and closes Activity.
- Drag persists location; long press reveals bottom-center trash; drop in trash stops service.
- Dedicated release signature; APK, source, signing backup and Korean instructions.

## Review Focus
- Missing/revoked overlay permission: no crash or invisible running service.
- Repeated Start: exactly one companion and one notification.
- Rotation / resizing / stale saved coordinates: companion remains reachable.
- Move beyond touch slop before long press: no trash activation; cancellation clears trash.
- Screen off / stop: no animation or lingering callback/window resources.
